eReader, two skins

Same pages, same DOM, two stylesheets. E-ink is today's look, kept as it is: pure black on white, 2 px borders, no shadows, no motion, 44 px targets. Soft is a new skin for laptops, phones and tablets: warm muted colours, hairlines and shadows instead of borders, Literata for headings so the library feels like the books in it.

Everything below is static HTML and CSS. The reading text is Literata, the UI is the system font, as in the app today. Covers are drawn in CSS to stand in for real ones.

Palette and type

Three themes, as today (Light, Sepia, Dark), each warm. The light theme is linen rather than white, the dark theme charcoal rather than black. 08

Side by side with e-ink

The very same HTML rendered twice. Left, today's stylesheet as an e-ink reader sees it with high contrast on. Right, the Soft skin. This is the whole idea: the markup and the scripts do not change, only which set of tokens and rules is loaded.

E-ink: 2 px black lines, bordered buttons, 8 px progress, a 44 px slider. Nothing translucent, nothing that fades.

Soft: hairlines, tinted pills, 3 px progress, shadows for depth. Hover reveals the options button; on e-ink it is always there.

09

How the switch works

Each page already runs a small boot script that reads the settings from localStorage and sets data-theme and data-eink on the root before the stylesheet applies, so there is never a flash. The skin rides on the same mechanism.

Which skin loads

  • A saved choice wins. The "High contrast (e-ink)" checkbox becomes a "Look" setting with two values, E-ink and Soft, in the Aa panel and on the Settings page, stored per device like the theme.
  • First visit: E-ink when the browser says it is one (Boox, Onyx, Kobo, Kindle, Tolino, PocketBook, reMarkable, Bigme, Hisense in the user agent), or when the device name typed at sign-in does. Otherwise Soft.
  • Existing devices that have the e-ink checkbox on keep the look they have. A Boox set up before this arrives changes nothing.
  • Themes stay Light, Sepia, Dark and System in both skins. Under E-ink they mean what they mean today.
// public/*.html boot script: one more line, before app.css loads
var eink = /Boox|Onyx|Kobo|Kindle|Tolino|PocketBook|reMarkable|Bigme|Hisense/i;
var skin = s.skin || (s.eink ? 'eink' : eink.test(navigator.userAgent) ? 'eink' : 'soft');
document.documentElement.dataset.skin = skin;

/* app.css: the differences that are just numbers become tokens ... */
:root[data-skin="eink"] { --bw: 2px; --radius: 6px; --shadow: none; --ease: 0s; }
:root[data-skin="soft"] { --bw: 1px; --radius: 12px; --shadow: var(--cover-shadow); --ease: .15s; }
.card { border: var(--bw) solid var(--line); border-radius: var(--radius); box-shadow: var(--shadow); }

/* ... and the few that are not sit in one block at the end */
:root[data-skin="soft"] .card { border: 0; }
:root[data-skin="soft"] .card .menu-btn { opacity: 0; }
:root[data-skin="soft"] .card:hover .menu-btn { opacity: 1; }

Scope of the change

  • CSS only for everything shown, except the two boot-script lines above and the Look setting (a few lines in settings.js and the two settings forms).
  • No template changes are needed. Three small ones would help and are optional: the icons in the book menu, the drop hint as one line, and the Finished label in sage.
  • Structure for later, not part of the skin: a bottom tab bar on phones, and a larger "continue reading" tile for the current book.
  • Tests are unaffected; the server does not know about skins.
